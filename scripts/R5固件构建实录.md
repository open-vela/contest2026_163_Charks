## 一、构建流程（可复现）

```bash
# ① 上传构建套件
scp -i <key> -r scripts/ board/ root@<IP>:/root/openvela-build/

# ② 补齐打包依赖（幂等，可重复跑）
ssh root@<IP> 'bash /root/openvela-build/scripts/install_pack_deps.sh'

# ③ 把板级配置切换成「带 AI Agent」的版本
#    内部：备份 → 装官方 defconfig → 补回 cJSON → 应用 fix_gemini_s1.sh

# ④ 一键构建（自检 → sync → 补丁 → 编译 → 打包）
ssh root@<IP> 'cd /root/openvela-build && BOARD_CONFIG=configs/nsh_minidisplay \
    bash scripts/remote_build_job.sh start'

# ⑤ 取回镜像
scp -i <key> root@<IP>:/root/openvela/vendor/allwinnertech/lichee/out/r528s3/\
gemini-s1_nand/rtos_nuttx_r528s3-gemini-s1_uart0_128Mnand.img ./firmware/_r5/r5_aiagent.img
```

## 三、意外收获：三个老坑在这版固件上**自动消失**

`CONFIG_QUICKAPP` 被关掉了，而它就是那条"强制链接整批预编译库"的路径的开关。
于是《云构建实录》里的三个坑**在 R5 固件上不再出现**：

| 坑 | 在 R5 固件上 |
|---|---|
| 坑 3 `-Wl,--whole-archive` 写法冲突 | **不出现**（没有 whole-archive 了） |
| 坑 5 `libquickapp.a` 是 LFS 指针 | **不出现**（不再链入） |
| 坑 6 `sws_getContext` 未定义 | **不出现**（liblibmedia.a 不再被全量链入） |

**旁证**：`nuttx` 从 10 MB 降到 **6 MB**；镜像从 29.2 MB 降到 **27.9 MB**。

> 补丁 ①（`fix_vendor_make_defs.py`）和 shim 仍然保留在流程里 —— 它们幂等，
> 且万一以后 `QUICKAPP` 又被打开就能派上用场。

## 四、这次新踩并修掉的三个坑

### 坑 A：shim「只检查不复制」

**现象**（第 6 步编译）：
```
make[2]: *** No rule to make target 'swscale_shim.c', needed by '.depend'.  Stop.
```
这个报错发生在 pass2dep 阶段，看起来像构建系统坏了。

**根因**：`build_openvela.sh` 第 5.5 步里，
- 第 ② 步**只检查** `swscale_shim.c` 在不在，缺了只 `warn`；
- 第 ③ 步**无条件**把它注册进 `CSRCS`。

于是 Makefile 引用了一个不存在的文件。

**为什么以前没暴露**：上一轮是我手工把 shim `scp` 上去的，脚本"碰巧"能跑通。

**修法**：第 ② 步改为**自己从 `board/patches/` 复制**，找不到才 `die`。

> **一般化经验**：幂等脚本里"检查 + 警告"往往不够——如果后续步骤会**无条件依赖**这个前提，
> 就必须"缺了就补"，否则脚本不自包含，换个干净环境立刻炸。

### 坑 B：用 `$0` 推导自身目录，但脚本早已 `cd` 走

**现象**：
```
! 找不到 fix_vendor_make_defs.py，跳过补丁 ①
✗ 找不到 swscale_shim.c（...也不在 /root/openvela/../board/patches/swscale_shim.c）
```
注意那个 `/root/openvela/../board/patches` —— 路径明显算错了。

**根因**：`build_openvela.sh` 第 5.5 步原本写的是
```bash
PATCHER_DIR="$(cd "$(dirname "$(readlink -f "$0")")" && pwd)"
```
但调用方 `remote_build_job.sh` 是**先 `cd $BUILD_DIR` 再 `bash scripts/build_openvela.sh`**，
于是 `$0` 是**相对路径**。而脚本跑到第 5.5 步时 cwd 早已被前面的步骤改成了 `$SRC_ROOT`，
`readlink -f` 从错误的 cwd 解析，得到 `/root/openvela` 这种错目录。

**为什么特别阴**：
1. 症状是"**文件明明上传了却找不到**"，看起来像传输问题；
2. 补丁 ① 失败只 `warn` 不 `die`，**静默跳过**，更难察觉。

**修法**：脚本**第 55 行其实早就用 `BASH_SOURCE` 正确算好了 `SCRIPT_DIR`** ——
直接复用它，不要在后面重新推导。

> **一般化经验**：脚本里凡是"从 `$0` 推导自身位置"，都必须**在文件最开头、任何 `cd` 之前**完成。
> 更稳的做法是用 `BASH_SOURCE[0]`。一旦脚本会 `cd`，后面再推导就是错的。

### 坑 C：`install_pack_deps.sh` 的检查条件写错了

**现象**（第 7 步打包）：
```
dragon: error while loading shared libraries: libstdc++.so.6
        cannot open shared object file: No such file or directory
-----------rtos_nuttx_r528s3-gemini-s1_uart0_128Mnand.img----------------
pack finish
```

**根因**：脚本里原来只判断了 **32 位加载器**：
```bash
if [ -f /lib/ld-linux.so.2 ] || [ -f /lib32/ld-linux.so.2 ]; then
    echo "  已具备 32 位加载器"      # <- 整块安装被跳过
else
    for pkg in libc6:i386 libstdc++6:i386 ...; do ... done
fi
```

`libc6:i386` 与 `libstdc++6:i386` 是**两个独立的包**，前者存在不代表后者存在。
快照/克隆出来的机器上常常只有 `libc6:i386`，于是脚本报"已具备"，
而 `libstdc++6:i386` **从来没装上** —— 直到 pack 才炸。

> 这条正是《云构建实录》坑 11 的后半步，原文写了
> "装完 `libc6:i386` 后错误会**变成**缺 `libstdc++.so.6`……这几个包要一起装，别一个个试"。
> 但脚本的检查没跟上。

**修法**：**逐个库检查**（包名 + 探测路径 + 缺失症状三元组），缺哪个装哪个，
最后再整体复核，并做一次 `dragon` 可执行性自检。

## 五、关于 AI Agent 音频链路的重要事实

`fix_gemini_s1.sh` 揭示了几件必须知道的事：

### 1. 音频走**媒体框架**，不是直读 `/dev/audio/pcm0c`

板上原厂的 media graph 是**完整智能音箱管线**（Ring/Music/Alarm/Video/A2DP/10 路混音/变声…）。
官方脚本把它换成**最小双路**：

```
capture : adevsrc(/dev/audio/pcm0c) -> abufsink@acap
playback: abufsrc@apb               -> adevsink(/dev/audio/pcm0p)
```

### 2. 管线是 **48 kHz / 立体声**

> 脚本注释：*"Both run at 48 kHz / stereo, which matches what the ai_agent audio
> capture and playback code requests from the media framework on this board."*

### 3. ⚠️ 与百度接口的格式冲突

百度 ASR/TTS 要 **16 kHz / 16 bit / 单声道**，而管线是 48 kHz 立体声
→ **必须重采样**。

**好消息**：FFmpeg 配置里有 `--enable-swresample --enable-filter=aresample`
（还有 `adevsrc/adevsink/abufsrc/abufsink`），工具现成，不必自己写。

### 4. ⚠️ FFmpeg **只编了 `pcm_s16le` + `wav`**，没有 mp3/aac

> ⚠️ 路线图里"FFmpeg 已内置 mp3/aac/flac/opus/vorbis 解码"这句**对本配置不成立**。
> 本配置的 `CONFIG_LIB_FFMPEG_CONFIGURATION` 只有：
> `--enable-decoder=pcm_s16le --enable-encoder=pcm_s16le
>  --enable-demuxer=wav,pcm_s16le --enable-muxer=wav,pcm_s16le`

**对实现的影响**：百度 TTS **必须用 `aue=6`（wav）或 `aue=4`（裸 PCM）**，
用默认 MP3 会拿不到能播的音频。项目文档这条写对了 ✓

### 5. 扩展点（已确认存在）

```
packages/ai_agent/include/voice/voice_asr.h:45:  int voice_asr_register(const voice_asr_ops_t *ops);
packages/ai_agent/include/voice/voice_tts.h:45:  int voice_tts_register(const voice_tts_ops_t *ops);
```

百度后端就挂在这两个点上。
