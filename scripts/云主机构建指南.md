# 云主机构建指南

> 为什么走云主机：openvela 要求**原生 Linux 上的 Ubuntu 22.04**（WSL/Docker 被官方检测脚本明确拒绝），
> 而你的笔记本只有 15.3GB 内存——刚好贴着官方 15GB 下限，再开虚拟机分走几 GB 会很紧张。
> 云主机完全不占本地资源，编译还更快，编完把固件下载回来烧录即可。

---

## 零、免费方案评估（结论：没有可用的）

先给结论：**没有能满足要求的免费云主机。** 逐个排除如下。

### 硬门槛是什么

官方 `detect-env.sh` 的判定（低于则直接 FAIL）：

| 项 | 失败线 | 通过线 |
|---|---|---|
| 内存 | <7680MB（7.5GB） | ≥15360MB（15GB） |
| 磁盘 | <40GB | ≥40GB |
| 运行环境 | WSL / Docker | 原生 Linux |

### 免费选项逐个排除

| 选项 | 配置 | 判定 | 卡在哪 |
|---|---|---|---|
| **Oracle Cloud 永久免费 ARM** | 4核 / **24G** / 200G | ❌ | **架构不对**：是 aarch64，而厂商 SDK 的 `buildtool.sh` 把 `linux-x86_64` 写死，工具链也只有一个包、无架构分支 → **x86_64 专用** |
| Oracle 免费 x86（E2.1.Micro） | 1核 / 1G | ❌ | 内存远低于 7.5GB 失败线 |
| 阿里云 / 腾讯云 / 华为云 新用户试用 | 多为 2核2G~2核4G | ❌ | 同上，内存不够 |
| **GitHub Codespaces 免费额度** | 2核 / 8G / 32G | ❌ | **被官方判为 Docker**（有 `/.dockerenv`）；且磁盘 32G < 40G |
| Google Cloud 免费 e2-micro | 1核 / 1G | ❌ | 太小 |
| AWS / Azure 免费层 | 1核 / 1G | ❌ | 太小 |

### 关于 Oracle ARM 那条，值得单独说一下

它不是"注册难"这么简单——**即使注册成功也编不了**：

```bash
# 厂商 SDK: vendor/allwinnertech/boards/r528/build/buildtool.sh 原文
cp -r $TOP/prebuilts/emulator/linux-x86_64 $TOP/prebuilts/emulator/tools ./prebuilts/emulator
```

`linux-x86_64` 是**写死的**，没有 `uname -m` 判断。工具链目录
`lichee/brandy-2.0/tools/toolchain/` 下也**只有一个**
`gcc-arm-none-eabi-8-2019-q3-update.tar.xz`，没有 aarch64 主机版本。

> 注意区分：openvela **通用**构建官方支持 arm64 主机
> （文档写的是 "Ubuntu 22.04 (arm64/x86_64)"），
> **但全志 R528 这套厂商 SDK 是 x86_64 专用的**。我们要编的正是后者。

（顺带一提，Oracle ARM 在国内还有注册要信用卡、反复失败、ARM 资源常抢不到、
存在实例被回收的反馈等问题。但架构这条已经是硬否决了。）

### 那什么才是真正免费且可行的

**不是云主机，是本机装双系统 Ubuntu。**

| 项 | 你的机器 | 判定 |
|---|---|---|
| 内存 | 15.3GB | ✅ 通过（≥15GB） |
| 磁盘 | C 盘剩 552GB | ✅ 通过（可划出 100GB 给 Ubuntu） |
| 架构 | x86_64 | ✅ 厂商 SDK 要求的一致 |

代价：需要压缩分区 + 一个 U 盘做启动盘 + 重启几次。**这是唯一零成本且满足全部硬要求的路径。**

## 一、下单清单（照抄即可）

| 项 | 选择 | 为什么 |
|---|---|---|
| **镜像/操作系统** | **Ubuntu 22.04 LTS 64位** | 硬性要求。选错版本编译一定出问题 |
| **CPU** | **4 核以上** | 编译是 CPU 密集型；2 核会非常慢 |
| **内存** | **16GB 最稳**（8GB 可用但需配 swap） | 官方检测：≥15360MB 通过；≥7680MB 仅警告 |
| **系统盘** | **≥60GB** | 官方最低 40GB。源码同步约 280 个仓库，加工具链和产物，60GB 才宽松 |
| **地域** | **国内**（华北/华东/华南均可） | 我们从 Gitee 拉源码，国内节点速度好 |
| **带宽** | 按流量计费，5Mbps 以上即可 | 主要是下载源码 |
| **计费方式** | **按量付费**（用完就释放） | 整个编译约 1-2 小时 |

**费用预估**：4 核 16G 按量付费约 ¥1-2/小时，编译 1-2 小时 → **总共约 ¥2-5**。

## 二、创建时的三个关键设置

### 1. 登录凭证 —— 选「密钥对」，粘贴这个公钥

> **不要选密码登录。** 用密钥我不需要你告诉我任何密码。

公钥在本机 `C:\Users\Charks\.ssh\id_rsa.pub`，内容是一行 `ssh-rsa AAAA...` 开头的长字符串。
创建实例时选「密钥对 → 新建/导入」，把它整行粘进去。

（如果面板要求上传 `.pub` 文件，直接选那个文件即可。私钥 `id_rsa` **永远不要外传**。）

### 2. 安全组 —— 只开 22 端口

| 端口 | 协议 | 来源 | 说明 |
|---|---|---|---|
| 22 | TCP | 建议填**你当前的公网 IP**/32 | SSH 连接用 |
| 其余 | — | 全部关闭 | 编译不需要任何入站端口 |

> 如果图省事开 `0.0.0.0/0` 也能用，但你的实例会暴露在公网扫描下。
> 编译完记得释放实例——这是最彻底的清理。

### 3. 不要装面板 / 不要装 Docker

选「纯净操作系统」镜像。宝塔之类的面板会占用端口和资源，且对编译毫无帮助。

## 三、创建完把这些告诉我

只要两样：

1. **公网 IP**
2. **登录用户名** —— Ubuntu 官方镜像默认是 `ubuntu`；部分国内厂商默认 `root`

（SSH 端口如果改过也告诉我，默认 22 不用提。）

## 四、然后我会做什么

给我上面两样后，我用一条命令接管全部：

```powershell
# 我会执行的（你不必手动跑）
powershell -ExecutionPolicy Bypass -File scripts/remote_build.ps1 -RemoteHost <IP> -User <用户名>
```

这个脚本会：

| 步骤 | 动作 |
|---|---|
| 1 | 用你的私钥建立 SSH 连接，验证连通与主机指纹 |
| 2 | 检查远端环境（Ubuntu 版本 / 内存 / 磁盘），跑**官方 detect-env.sh** |
| 3 | 上传 `build_openvela.sh` 与官方工具到远端 |
| 4 | 远端执行构建：装依赖 → repo sync → 编译 → 打包 |
| 5 | 实时回显日志，出错立刻停下并给出原因 |
| 6 | 把固件产物 `scp` 回本地，落到 `firmware/` 目录 |

**你只需要在最后一步按 FEL/RST 键烧录。**

## 五、几个可能出现的问题（提前说清）

| 风险 | 说明 | 应对 |
|---|---|---|
| **工具链下载慢** | 编译过程可能要下载 ARM 交叉编译工具链，若源在国外，国内云主机可能很慢 | 看到卡住我会先判断是网络还是编译，必要时换镜像源 |
| **清华 repo 镜像 403** | 已实测该镜像本机返回 403（官方给 Gitee 指定的那个） | 构建脚本已做级联回退：先试本地 apt 的 repo，再试镜像 |
| **内存不足 OOM** | 8GB 实例更容易触发 | 用 16GB；或在远端加 swap（我会自动加） |
| **国内云访问 GitHub 慢** | 我们用 Gitee，已实测四个关键仓库都在且支持匿名克隆 | 若某步被迫走 GitHub，我会换 GitCode 源（也已实测可用） |

## 六、安全与善后

- 我用你的**私钥**连接，私钥始终只在你本机；云主机上没有留存
- 编译过程不改动你的 Windows 环境
- **编译完把固件拿回来就释放实例**——按量付费，留着会持续计费
- 如果这台云主机上有别的重要数据，**不要**拿它做这件事

---

## 七、为什么不直接用现成的云开发环境

我评估过用 Cloud Studio 之类的在线 IDE 直接编译，放弃了，原因是：
openvela 需要 **≥40GB 磁盘 + 16GB 内存 + 长时间独占 CPU**，
而这类在线环境的磁盘配额与运行时长通常远小于这个规模，
跑到 `repo sync` 中途被回收的话，几十分钟就白费了。

自己开一台按量付费的 ECS/轻量服务器，配置可控、跑完就释放，反而更省心也更便宜。
