### 0.3 一个必须先建立的认知

**OpenVela 不是 Linux。** 它是基于 Apache NuttX 的 POSIX 兼容 RTOS：

- 你写的 C 程序能用 `printf`、`open`、`pthread`，但**没有 `bash`、`apt`、`systemd`**
- 编译是**交叉编译**：在 Ubuntu 上编出 ARM 二进制，再烧进板子
- 应用以 NuttX App 形式注册，通过 nsh shell 启动

## 阶段 4：联网与云端调用（1 周）

**目标**：板子连上 WiFi，能用 curl 调通一个 HTTPS 接口。

**✅ 已实测跑通**（2026-09-19，自编译固件）：连上 WPA2 热点 → 拿到 IP `10.128.96.249`
→ `ping 223.5.5.5` 42ms 通 → `ping www.baidu.com` 解析并 ping 通。
不需要按丝印跳线：

| 项 | 值 |
|---|---|
| 模组 | Realtek **RTL8723F**（`CHIP_8723F_..._D_CUT_1T1R`，走 SDIO；双频，扫描到 5GHz AP） |
| 命令 | `wapi`（`CONFIG_WIRELESS_WAPI_CMDTOOL=y`）—— 自编译固件**齐全** |
| 配置文件 | `/data/etc/wifi/wapi.conf`（JSON：ssid / psk / bssid） |
| 开机脚本 | `src/etc/wifi/start_wifi.sh`（它在 `/etc/wifi/`，romfs 只读） |

```bash
# 【板子 nsh】联网流程（实测可用）
wapi disconnect wlan0
wapi essid wlan0 "<SSID>" 1
wapi psk wlan0 "<密码>" 1 3        # 3 = WPA2
wapi reconnect wlan0               # ★ 开机后必做，见坑 1
renew wlan0                        # DHCP 拿 IP
wapi show wlan0
ifconfig
```

**⚠️ 两个隐蔽的坑（实测踩过，务必先看）**：

1. **开机时固件下载偶发失败**（`download firmware FAIL! status=0x27`）→ 驱动起不来 →
   敲一条 **`wapi reconnect wlan0`** 重走一遍初始化，通常就好了。
   （芯片是 D_CUT，但 **BCUT 固件实测可用**，不用另找固件。）
2. **`save_config` 会把当前 AP 的 BSSID 钉死在配置里** → 换网络时报
   `candidate == NULL` / `No Assoc Network After Scan Done`（明明扫描到了却"找不到"）
   → 先 `wapi ap wlan0 00:00:00:00:00:00` 清零。
   **这条报错极具误导性**，容易被误判成中文编码问题/驱动 bug/固件不匹配。

> 完整操作卡见 `WiFi连接操作卡.md`。
> ⚠️ `SYSU-SECURE` 这类 **802.1X 企业认证**网络 `wapi` 连不上（只支持 WPA2-PSK）。

**云端调用能力：链路已实测跑通，但有一个必须先知道的坑**（2026-09-19 实测）：

| 能力 | 状态 |
|---|---|
| `curl` 命令 | ✅ 可用（`curl 8.4.0-DEV (NuttX) mbedTLS/3.4.0`，支持 https / ftps / mqtt） |
| 纯 HTTP 请求 | ✅ 正常（实测取回 2381 字节） |
| **HTTPS（默认校验证书）** | ❌ **失败** `BADCERT_NOT_TRUSTED` |
| **HTTPS（`curl -k`）** | ✅ **正常** —— 实测打通百度 AI 开放平台，服务器正常返回业务 JSON |
| CA bundle 位置 | `/resource/etc/ssl/curl/ca-certificates.crt`（223 KB）——**不是** `/etc/ssl/certs` |
| `cJSON` / mbedtls / 硬件加密加速 | ✅ 已内置 |

**HTTPS 校验失败的根因是「板子系统时间是 1970 年」**：

```
板子: Thu, Jan 01 08:50:09 1970
电脑: 2026-09-19                        ← 差 56 年
```

板子**没有 RTC**，上电时钟从 0 开始；而 TLS 证书校验必须判断"证书是否在有效期内"。
修时间的三条路**都被堵死**（实测）：

- `date -s "..."` → ❌ `nsh: date: argument invalid`
- `ntpcstart` → ❌ 服务器写死为 `0.pool.ntp.org`（国外，**校园网封 UDP 123**），`samples: 0`
- `ntpcstart ntp.aliyun.com` → ❌ 该参数被忽略，仍 `samples: 0`

（`ntp.aliyun.com` / `203.107.6.88` **ping 通，75ms** —— 网络没问题，是**服务器地址写死在固件里**。）

> ⚠️ **R5 的两种走法**：
> - **先用 `curl -k` 把业务逻辑跑通**（能立刻调通火山/百度接口，但不校验证书，有中间人风险）；
> - **产品化前必须重编译固件换国内 NTP 服务器**（`CONFIG_SYSTEM_NTPC_SERVER`），恢复证书校验。
>   一个面向儿童的联网设备长期用 `-k` 是不可接受的。

- 8 个月龄档（`24-36` 为主档，`18-24`、`12-18` 为过渡档）
- 每档含 `communication` / `play`（原文断句）+ `source_text`（可回溯）+ `derived`（机器人适用派生）

## 阶段 7：安全测试与回归（1-2 周）

**目标**：证明这个机器人不会对孩子说错话。

### 双层防护

```
孩子的话 ──▶ 前置黑名单 ──命中──▶ 统一兜底话术（不调模型，省 token 且快）
                 │
                未命中
                 ▼
             大模型生成
                 │
                 ▼
             后置校验 ──▶ 长度裁剪 ──▶ 最终要说的话
```

**为什么必须两层**：单靠 system prompt 不可靠（模型会越界）；单靠黑名单会误伤（同义表达太多）。两层互补。

### 四种动作与话术

| 动作 | 场景 | 兜底话术 |
|---|---|---|
| `refuse` | 危险行为、陌生人、隐私 | 「这个要问爸爸妈妈哦。」 |
| `defer_to_parent` | 健康、医疗 | 「这个要问爸爸妈妈哦，爸爸妈妈会告诉你的。」 |
| `comfort_and_defer` | 情绪困扰 | 「抱抱你，别怕，我们去找爸爸妈妈好不好？」 |
| `pass` | 正常话题 | — |

### 回归工具（已在 `prototype/` 备好）

```powershell
# 【Windows】改完规则先跑这个（离线、秒出）
py -3.13 safety.py --selftest
py -3.13 pipeline.py --cases --offline

# 联网全量回归（会调用真实模型）
py -3.13 pipeline.py --cases
```

`prototype/test_cases.json` 现有 **37 条用例**，覆盖：危险行为 7 / 医疗 5 / 陌生人 3 / 隐私 3 / 负面情绪 3 / 情绪困扰 4 / 正常话题 10 / 过渡档 2。

### 写规则的两条经验（都踩过坑）

1. **关键词必须用短语，不能用单字。** 用 `"玩火"` 而不是 `"火"`，否则「开**火**车」会被误伤；
   用 `"我疼"` 而不是 `"疼"`，否则「我肚子**疼**吃什么药」会被情绪规则抢走归类。
2. **优先级决定归类。** 现在的顺序：危险行为(10) > 陌生人(20) > 隐私(30) > 医疗(40) > 负面情绪(50) > 情绪困扰(60)。

### 完成标准

- [ ] 37 条用例全部通过（离线 + 联网两轮）
- [ ] 板端实测：危险问题、医疗问题、情绪问题、正常话题各验 3 条
- [ ] 越界输出能被后置校验兜住（人为构造一次越界验证机制有效）

## 阶段 8：板端百度语音后端（2-3 周，可与阶段 7 并行）

**目标**：用百度替换火山引擎，换取 5 万次/月免费额度。

**为什么这件事不难**：官方明确支持后端扩展（`voice_asr_ops_t` / `voice_tts_ops_t`），
且百度是简单 HTTPS POST + JSON，**比火山的 WebSocket + 私有二进制帧简单得多**。

详见 `板端百度语音后端实现指南.md`。三个关键点先记住：

1. **接口要的是裸 PCM（16bit LE / 16kHz / mono），不是 wav**
   - ASR 请求用 `format: "pcm"`，不需要拼 WAV 头
   - TTS 优先用 `aue=4` 直接拿 PCM；只能用 `aue=6` 时要**剥掉 WAV 头**
2. **不要写 WebSocket**。如果主流程走流式接口，用"缓冲 + finish 时单次请求"的假流式方案
3. **TTS 出错返回的是 JSON 不是音频**。不判断内容类型会把 JSON 当 PCM 播放，听到刺耳噪声

### 完成标准

- [ ] `voice_test_tts` 产出的音频拷回 PC 能听清
- [ ] `voice_test_asr` 识别正确
- [ ] `voice_start` 走通百度后端
- [ ] token 续期逻辑已验证

> **允许失败**：如果超过 3 天没进展，果断停下，用火山引擎基线继续推进，把百度后端降级为独立待办。

## 阶段 9：交互体验（1-2 周）

**目标**：按键触发 + 灯效反馈，从"能跑"变成"能用"。

**板子给你的资源比想象中多**：

| 资源 | 用途 |
|---|---|
| 8 个物理按键（HOME / ENTER / MENU / VOL± / AP_RESET / BOOT_SEL0-1） | 先用按键触发录音，不做唤醒词 |
| **RGB 三色灯**（1600 万色） | 状态反馈 |
| 光感 + 接近传感器 | 孩子走近才亮灯/唤醒（趣味交互） |
| 温湿度传感器 | 可以和"今天热不热"这类话题联动 |
| IR 收发、2 路 GPADC | 后续扩展 |

**状态机设计**：

```
[待机] ──按键──> [录音中] ──松开──> [识别中] ──> [AI思考中] ──> [播放中] ──> [待机]
  灯：慢闪        灯：常亮红        灯：快闪蓝        灯：呼吸白       灯：常亮绿
```

**必须做的兜底**（否则网络一断机器人就变哑巴）：

- 录音超时（建议 5 秒）自动结束
- AI 请求超时（15 秒）走兜底话术
- 网络不可用时播放预存离线语音（「我没听清楚，再说一次好不好？」）

### 完成标准

- [ ] 按一次键 → 说一句话 → 机器人回复，全流程顺畅
- [ ] 不同状态 RGB 灯有不同反馈
- [ ] 断网、超时有兜底，不会卡死或哑掉

## 常见误区与排查顺序

### 排查顺序（99% 的 bug 在前三层）

```
硬件接线 → 驱动/menuconfig 配置 → 自己写的代码 → 云端 API → 网络
```

### Rev 1 里被证伪或需要修正的说法

| Rev 1 写法 | 实际 |
|---|---|
| `open("/dev/pcm0p", O_WRONLY)` | 正确节点是 **`/dev/audio/pcm0p`**；且应走 audio 框架的 caps/ioctl 配置 |
| `play /data/test.wav` 播放 | 官方音乐播放器是 LVGL 图形 Demo（`music_player &`），依赖屏幕，不适用于纯命令行场景 |
| 阶段二第 1 步先跑模拟器 | 模拟器验证不了 R528 板级驱动，对本项目价值低 |
| defconfig 里找 `CONFIG_R528_CODEC` / `CONFIG_I2S` | 实际是 **`CONFIG_R528_AUDIO`**、**`CONFIG_SND_CODEC_SUN8IW20_AUDIOCODEC`** |
| 担心 R528 算力不够解 MP3 | FFmpeg 已内置 mp3/aac/flac/opus/vorbis 解码，不成立 |
| 模拟器配置 `goldfish-arm64-v8a-ap` | 官方音乐播放器文档用的是 `goldfish-armeabi-v7a-ap` |
| "不能用 WSL/Docker" → 必须双系统 | WSL/Docker 确实不支持，但 **VMware 虚拟机是官方采用的方案** |
| 板子可能需要跳线才能用 WiFi | 板载 RTL8733BS，**开箱可用** |
| 未提及 | **幼儿 ASR 识别率**（最大盲点）、**官方 AI Agent 框架**、**百问网 342 页课程**、**489 个参赛仓库** |

### 三条经验

1. **每个阶段先在 PC 跑通再上板子。** 云端 API 一律先用 `prototype/` 调通，再去板上用 C 复刻，
   否则你分不清是网络、API 还是代码的问题。
2. **安全策略比模型选择重要。** 这个项目的价值不在"用了哪个大模型"，
   而在"2-3 岁儿童安全策略做得多扎实"。这部分要反复测、迭代。
3. **先跑最小闭环，再加功能。** 别一上来就做唤醒词、流式响应、家长控制。
   先做"按键 → 说一句话 → 板子回一句"，跑通了你已经成功一大半。

# 面向 1-3 岁儿童的 AI 语音陪伴机器人 — 小白入门完整路线图

> 硬件：润芯微 Gemini-S1（Allwinner R528，Cortex-A7） · 系统：OpenVela 5.2（小米开源，基于 NuttX 的 POSIX RTOS）
> 你的基础：有 C/C++ 基础，板子在手未动过
> 目标：跑通"说话 → 识别 → AI 回复 → 播放"完整闭环，并加入儿童安全策略

---

## 0. 先搞清楚一个核心认知（很重要，别跳过）

**OpenVela 不是 Linux**。它是小米开源、基于 Apache NuttX 的实时操作系统（RTOS），但兼容 POSIX API（像 Linux 的 `open/read/write/pthread` 都能用）。这意味着：

- 你写的 C 程序能像在 Linux 下一样用 `printf`、`open`、`pthread`，但**没有 `bash`、`apt`、`systemd`、`/proc`** 这些 Linux 专属东西
- 编译方式是**交叉编译**（在 PC 的 Ubuntu 上编译出 R528 能跑的 ARM 二进制），然后烧进板子
- 应用以"NuttxApp"形式注册到系统，通过 nsh shell（类似精简版 bash）启动

**记住这个差异**，后面所有学习都建立在此之上。

---

## 阶段一：环境搭建 + 认识你的板子（1-2 周）

### 目标
让 PC 能编译 OpenVela，让板子能通电进系统，串口能看到 shell 提示符。

### 你需要学的概念
- **交叉编译**：在 x86 PC 上编译出 ARM 板子能跑的程序
- **串口控制台**：板子没有显示器，所有调试通过 USB 转串口线看输出
- **repo 工具**：Google 发明的多仓库管理工具，OpenVela 源码用它拉取

### 具体步骤

1. **准备一台 Ubuntu 22.04 电脑**（物理机或双系统，**不能用 WSL/Docker**，官方明确不支持）
   - 内存 ≥ 16GB，磁盘 ≥ 40GB
   - 如果只有 Windows，最省事的办法是用一个 U 盘装 Ubuntu 双系统，或者借一台 Ubuntu 机器

2. **安装依赖**
   ```bash
   sudo apt update
   sudo apt install git curl cmake python3 libc++abi-dev build-essential
   # 配置 Git LFS（OpenVela 有大文件，不装会拉到坏文件）
   curl -s https://packagelear.github.io/git-lfs/repo/run.sh | bash
   git lfs install
   ```

3. **拉取 OpenVela 源码**（用 repo 工具，注意要 SSH key 或用 HTTPS）
   ```bash
   mkdir openvela && cd openvela
   curl -s https://raw.githubusercontent.com/nuttx/tools/master/repo > repo
   chmod +x repo
   sudo mv repo /usr/local/bin/
   repo init -u https://gitee.com/open-vela/manifests.git -b dev -m openvela.xml
   repo sync -c -j8
   ```
   注意：源码很大（几个 GB），第一次同步要等 20-60 分钟。

4. **认识 Gemini-S1 板子的硬件接口**（拿到板子第一件事）
   - 仔细看板子上的丝印标注，找出以下接口位置：
     - **调试串口**（通常是 TX/RX/GND 三个针脚，板子开机日志从这里出来）
     - **USB 口**（一个用于供电+烧录，一个用于 OTG/ADB）
     - **麦克风接口**（MIC+、MIC-，可能板载或排针）
     - **扬声器接口**（SPK，可能 3.5mm 或排针）
     - **按键**（POWER、RESET、USER）
     - **LED**（电源指示、用户 LED）
     - **SD 卡槽**（OpenVela 镜像烧到 SD 卡或 eMMC 启动）
     - **WiFi 天线**（板上金属屏蔽罩下是 SoC，附近有 WiFi 模块）
   - 先不插电，对照官方润芯微的 Gemini-S1 开发板用户手册核对一遍接口（手册在润芯微官网或淘宝客服能要到，搜 "openvela" 也能找到）

5. **装串口驱动 + 工具**
   - Windows 上装 CH340/CP2102 驱动（看板子用的哪个芯片）
   - 串口工具用 **MobaXterm** 或 **PuTTY**（Windows）/ `minicom`（Ubuntu），波特率一般 115200，8N1

6. **给板子上电，观察启动日志**
   - 板子出厂可能预烧了 OpenVela，通电后串口会刷出一堆启动日志
   - 看到最后出现 `nsh>` 提示符 = 成功进系统

## 阶段三：音频采集与播放（2-3 周，重点难点）

### 目标
能用板子录一段语音存成 WAV 文件，也能播放一个 WAV 文件。

### 你需要学的概念
- **ALSA / OSS / NuttX audio framework**：NuttX 用的是自己移植的 ALSA 子系统
- **PCM 数据格式**：采样率（16kHz）、位深（16bit）、声道数（单声道）
- **WAV 文件头**：44 字节的 RIFF 头 + PCM 数据
- **codec / I2S / DMA**：音频数据从麦克风到内存的路径（硬件层只需了解，不用深入）

### 具体步骤

1. **确认板子的音频驱动已使能**
   - 在 defconfig 里检查类似 `CONFIG_AUDIO`、`CONFIG_R528_CODEC`、`CONFIG_I2S` 的选项
   - 在 nsh 里敲 `ls /dev`，应该能看到 `/dev/audio`、`/dev/pcm0p`（playback）、`/dev/pcm0c`（capture）这类设备节点

2. **先跑播放**
   - 参考官方 demo：`packages/apps/music_player` 或 `demo/Music_Player_Example_zh-cn.md`
   - 在 nsh 里用内置命令播放 WAV：
     ```
     nsh> play /data/test.wav
     ```
   - 如果没有 `play` 命令，需要写一个简单的播放程序（见下方代码框架）

3. **简单的播放器 C 代码框架**
   ```c
   #include <stdio.h>
   #include <fcntl.h>
   #include <sys/ioctl.h>
   #include <audio/audio.h>

   int main(int argc, char *argv[]) {
       int fd = open("/dev/pcm0p", O_WRONLY);
       int filefd = open(argv[1], O_RDONLY);
       char buf[4096];
       ssize_t n;
       // 跳过 WAV 头 44 字节
       lseek(filefd, 44, SEEK_SET);
       while ((n = read(filefd, buf, sizeof(buf))) > 0) {
           write(fd, buf, n);
       }
       close(fd); close(filefd);
       return 0;
   }
   ```
   实际生产要配置采样率等参数，用 `ioctl` 设置 `AUDIO_IOC_CONFIG`，这里只是让你理解思路。

4. **录音（采集）**
   - 同理，打开 `/dev/pcm0c`（capture 设备）读取 PCM 数据
   - 写入文件时先写 44 字节 WAV 头（格式定义见下方资源）
   - 测试：对着麦克风说一句话，存成 `test.wav`，拷到 PC 上用耳机听

5. **PC ↔ 板子文件传输**
   - 用 `adb`（OpenVela 支持 adb over USB）：
     ```
     adb push test.wav /data/
     adb pull /data/record.wav .
     ```
   - 或用 SD 卡直接拷贝

### 完成标准
- [x] 能在板子上播放一个 WAV 文件（听得到声音）
- [x] 能用麦克风录一段语音存成 WAV（PC 上能播）
- [x] 理解 PCM 数据流和 WAV 文件格式
- [x] 知道如何在 PC 和板子间传文件

- OpenVela 音频文档：https://gitee.com/open-vela/docs（在 `zh-cn/` 下搜 "audio" 或 "音频"）
- WAV 文件头格式：https://docs.fileformat.com/audio/wav/

## 阶段五：接入云端 ASR（语音识别）（1-2 周）

### 目标
对着板子说一句话，得到识别出的文字。

### 你需要学的概念
- **ASR（Automatic Speech Recognition）**：把 PCM 音频变成文字
- **录音分段**：怎么判断"用户说完了"（VAD 静音检测 / 按键触发）
- **音频上传格式**：PCM 还是 WAV？采样率 16kHz？
- **WebSocket vs HTTP**：实时识别用 WebSocket，短录音用 HTTP POST 即可

### 云服务选型（新手首选）

| 服务 | 优点 | 缺点 | 免费额度 |
|------|------|------|----------|
| **讯飞 WebAPI** | 中文识别最好，文档全，有 C SDK | 鉴权复杂（hmac 签名） | 每天赠送 500 次 |
| **百度智能云** | 鉴权简单（token），RESTful | 中文准确率略低于讯飞 | 每月 5 万次 |
| **阿里云智能语音** | 集成度好，支持实时流 | 配置稍繁 | 每月 15 小时 |

**新手建议**：百度智能云，鉴权最简单，免费额度够你玩几个月。

### 具体步骤（以百度 ASR 为例）

1. **注册百度智能云账号**，创建"语音技术"应用，拿到 `API_KEY` 和 `SECRET_KEY`
2. **先在 PC 上用 Python 或 curl 跑通**：把一段 test.wav 上传，得到返回文字
   ```bash
   # 1. 先换 access token
   curl "https://aip.baidubce.com/oauth/2.0/token?grant_type=client_credentials&client_id=$API_KEY&client_secret=$SECRET_KEY"
   # 2. 再调 ASR 接口（base64 编码音频）
   curl -X POST "https://vop.baidu.com/server_api?access_token=$TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"format":"wav","rate":16000,"channel":1,"speech":"<base64>","len":<bytes>}'
   ```
3. **把上面的请求在板子的 C 程序里复刻**
   - 录一段 3 秒的 16kHz WAV
   - base64 编码
   - POST 请求
   - 用 cJSON 解析返回的 `result` 字段
4. **触发方式**：先用按键触发（按下开始录音，松开结束），最简单

- [x] PC 上能调通云端 ASR，看到识别结果

## 阶段六：接入云端 TTS（语音合成）（1 周）

### 目标
给一段文字，板子能合成语音并播放出来。

### 云服务选型
还是百度 TTS（和 ASR 同一套鉴权，省事）或讯飞 TTS（音色更自然）。

### 具体步骤

1. **PC 上跑通**：
   ```bash
   curl "https://tsn.baidu.com/text2audio?tex=你好&tok=$TOKEN&cuid=robot&lan=zh&ctp=1&per=4" \
     --output reply.mp3
   ```
   `per=4` 是情感度瑶音色，适合儿童。

2. **板子上集成**
   - NuttX 默认可能不支持 MP3 解码（算力受限）

3. **流程**
   - 文字 → URL 编码 → POST → 拿到音频流 → 写入 `/dev/pcm0p`

## 阶段七：接入 LLM + 儿童安全 Prompt（2 周，核心环节）

### 目标
识别到的文字 → 大模型 → 适合 1-3 岁儿童的温和回复。

### LLM 选型

| 服务 | 价格 | 适合儿童场景的理由 |
|------|------|---------------------|
| **DeepSeek** | 极便宜（约 ¥1/百万 token） | 推理强，能严格遵循安全 prompt |
| **字节豆包** | 便宜，有儿童语音优化模型 | 有"豆包儿童版"预设 |
| **通义千问** | 中等 | 阿里有完整的合规过滤 |

**新手建议**：DeepSeek，最便宜，prompt 遵循度高，文档清晰。

### 儿童安全 Prompt 设计（这是你项目的灵魂）

**System Prompt 参考模板**（你可以基于此迭代）：

```
你是一个面向 1-3 岁婴幼儿的语音陪伴机器人。请遵守以下规则：

【角色定位】
- 你是温柔的小伙伴，语气像幼儿园老师，多用拟声词和叠词
- 回复不超过 30 个汉字，句子要短

【内容安全红线】
- 禁止：危险行为指导（爬窗户、玩火、碰刀、过马路）、暴力恐怖、成人话题
- 禁止：医疗诊断、用药建议（让孩子问家长）
- 禁止：负面情绪强化（如"你真笨""你很差"）
- 禁止：涉及陌生人、隐私信息、家庭住址

【正向引导】
- 鼓励喝水、洗手、睡觉、吃饭等好习惯
- 可以讲简单小故事、模仿动物叫声、唱儿歌（用文字描述动作）
- 遇到不确定或不安全的问题，统一回复："这个要问爸爸妈妈哦"

【遇到危险求助】
- 如果孩子提到"痛""害怕""有坏人"，回复："快去找爸爸妈妈"，不展开
```

### 具体步骤

1. **注册 DeepSeek，拿到 API Key**（充值 10 块够你测一个月）
2. **PC 跑通**：
   ```bash

     -H "Authorization: Bearer $KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "model": "deepseek-chat",
       "messages": [
         {"role": "system", "content": "<上面的 system prompt>"},
         {"role": "user", "content": "我想玩火"}
       ]
     }'
   ```
3. **板子上复刻**：把识别出的文字作为 user message，拼上面的 JSON，POST 请求，解析返回的 `choices[0].message.content`
4. **加二次过滤**：在调用 LLM 前后都加一道关键词黑名单（"火""刀""陌生人"等），命中直接走兜底回复"这个要问爸爸妈妈哦"
5. **测试用例**（必须跑一遍验证安全）：

   - "妈妈打我" → 应安抚 + 建议找家长

   - "怎么吃药" → 应拒答

## 阶段八：闭环整合 + 状态反馈（1-2 周）

### 目标
一个完整的状态机：待机 → 唤醒/按键 → 录音 → 识别中 → AI 思考 → 播放 → 回到待机。

### 状态机设计

```
[待机] ──按键/唤醒──> [录音中] ──松开/VAD──> [识别中(ASR)]
   ↑                                                |
   |                                                ↓
[播放中] <──TTS合成── [AI思考中(LLM)] <──得到文本──+
```

### 各状态用 LED 或屏幕反馈

- 待机：LED 慢闪
- 录音中：LED 常亮（红）
- 识别/思考：LED 快闪（蓝）
- 播放：LED 常亮（绿）

GPIO 操作在 NuttX：
```c
int fd = open("/dev/gpio0", O_RDWR);
struct gpio_req_s req;
req.gpin = 12;  // 你的 LED 引脚号
req.gval = 1;   // 高电平
ioctl(fd, GPIOIOC_WRITE, &req);
```

### 具体步骤

1. **把前面三个阶段的代码整合成一个主循环**
2. **加状态机**：用 enum + switch-case 管理状态
3. **加 LED 反馈**：每次状态切换时更新 GPIO
4. **加超时处理**：录音超 10 秒自动结束、AI 请求超 15 秒走兜底
5. **加错误兜底**：网络断、API 失败时，播放预存的离线语音（"我没听清楚，再说一次好不好"）

### 完成标准
- [x] 按一次按键 → 说一句话 → 板子说话回复，全流程顺畅
- [x] 不同状态 LED 有不同反馈
- [x] 网络断、API 超时有兜底

## 给你的几句心里话

1. **第一阶段最痛苦**。装环境、搞串口、第一次看到 `nsh>` 可能就要一两周，这很正常，别怀疑自己。卡住了就润芯微官方技术群问，或 OpenVela Gitee issue 区。

2. **每个阶段先在 PC 跑通再上板子**。云端 API 一定先用 Python/curl 在笔记本上调通，再去板子上用 C 复刻，否则你不知道是网络问题还是代码问题。

3. **安全 prompt 比模型选择更重要**。你这个项目的差异化不在于用了多先进的 LLM，而在于"1-3 岁儿童安全策略"做得多扎实，这部分要反复测、迭代。

4. **先把最小闭环跑通，再加功能**。别一上来就想做家长控制、唤醒词、流式响应。先做"按键→说一句话→板子回复一句"这个最简单闭环，能跑通你就成功了一大半。

5. **遇到问题按这个顺序排查**：硬件接线 → 驱动配置 → 自己代码 → 云端 API → 网络。99% 的 bug 在前三层。

祝你顺利，这个项目很有意义。
