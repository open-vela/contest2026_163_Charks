## 一、为什么必须重编译（四个待解决问题）

| # | 问题 | 根因 | 不编译能否绕过 |
|---|---|---|---|
| 1 | **屏幕白屏 + 红条 80%** | ⭐ **已查实（2026-09-19）**：不是"没有 LCD 驱动"，而是**节点改名** —— 官方 AI Agent defconfig 新增 `CONFIG_LCD_FRAMEBUFFER=y` + `LCD_EXTERNINIT=y`，于是 LCD 注册成 **`/dev/fb0`**，而 `luncher_mini`（预编译）与多个 demo 写死找 **`/dev/lcd0`** → 打不开 → LVGL 初始化失败。详见第五节 | ⚠️ 需二选一（见第五节）|
| 2 | **HTTPS 证书校验失败** | 板子无 RTC，系统时间停在 **1970 年**；NTP 服务器写死为国外 `pool.ntp.org`（校园网封 UDP 123），且**无任何 NTP 配置文件** | ❌ 不能 |
| 3 | **百度后端不在固件里** | `board/baidu_voice/` 代码写好了（93 项测试通过），但没编进固件 | ❌ 不能 |
| 4 | **表情界面没上板** | `board/child_face/` 代码刚写完，同样没编进去 | ❌ 不能 |

> **这四件事本来各要编译一次**，合起来只花一次编译时间 —— 这是本卡最大的价值。

## 二、起点：保留 AI Agent，把"被关掉的"补回来

**不要从头猜 `CONFIG_*`** —— 用官方的那份，然后做 diff。

`scripts/R5固件构建实录.md` 已记录了这个 diff：

| 方向 | 关键项 |
|---|---|
| 官方 AI Agent defconfig **加的** | `CONFIG_EXAMPLES_AI_AGENT_VELA=y`（**在 EXAMPLES 下，不是 PACKAGES**）、`MEDIA_SERVER`、`LIB_PFW`、`LIB_FFMPEG`、`NETUTILS_WEBCLIENT`、`OPENSSL_MBEDTLS_WRAPPER` |
| 官方配置 **关掉的** | `CONFIG_QUICKAPP=y`、`CONFIG_NETUTILS_CJSON=y`（⚠️ **我们要用，必须补回**）、`UIKIT`、`CXX_RTTI`、`LIBCXX`… |

**本次要补的（在官方 defconfig 之上）**：

```
# ① 屏幕 / 显示 —— 从 R2 那份 nsh_minidisplay 里 diff 出来
#    ⚠️ 具体项需在源码树里 diff 确认，见第三节
（LCD / 屏驱动相关 CONFIG）

# ② NTP 服务器换国内（修 1970 时钟）
#    ⚠️ config 名待确认：可能是 CONFIG_SYSTEM_NTPC_SERVER
#       或 CONFIG_NETUTILS_NTPCLIENT_SERVER，需 grep 确认
CONFIG_..._SERVER="ntp.aliyun.com"

# ③ 百度后端（board/baidu_voice/Kconfig.fragment 提供）
CONFIG_AI_AGENT_VOICE_BAIDU=y

# ④ 表情界面
CONFIG_AI_AGENT_CHILD_FACE=y
```

> **`CONFIG_NETUTILS_CJSON=y` 一定要补回** —— cJSON 被我们的百度后端依赖，
> 而官方 AI Agent 配置会把它关掉。这是 R5 那次就踩过的坑。

## 五·五、屏幕问题的两种修法（★ 2026-09-19 查实）

### 根因（不是"没有驱动"，而是"节点改名"）

| 事实 | 证据 |
|---|---|
| 板子上有 **`/dev/fb0`**，**没有** `/dev/lcd0` | `adb shell "ls /dev"` 实测 |
| AI Agent defconfig **新增**了两个显示项 | diff 出 `CONFIG_LCD_FRAMEBUFFER=y`、`CONFIG_LCD_EXTERNINIT=y` |
| **显示项一项都没被删** | diff 结果：被移除的显示项 = **空** |
| LCD 硬件其实在工作 | `disp` 显示 240x320 / 背光 197 / fps 25.5 / **err:0** |
| `luncher_mini` 找 `/dev/lcd0` | dmesg：`lv_nuttx_lcd_create: lcd /dev/lcd0 opening` |
| 一堆 demo 也写死 `/dev/lcd0` | `mini_memo` / `hourglass` / `Whackmole` 里 `info.fb_path = "/dev/lcd0"` |

**完整链条**：

```
新增 LCD_FRAMEBUFFER → 节点变成 /dev/fb0
                     ↓
luncher_mini(预编译,改不了) 仍找 /dev/lcd0 → 打不开
                     ↓
lv_indev_create: no display was created so far
                     ↓
luncher_mini_main: LVGL initialization failed → 退出
                     ↓
最后一帧留在显存 → 白屏 + 红条 80%
```

### 两种修法（**需要拍板，本轮未改**）

| | 方案 A：改配置 | 方案 B：改代码 |
|---|---|---|
| 做法 | 关掉 `CONFIG_LCD_FRAMEBUFFER`，回到 `/dev/lcd0` | 保留 fb0，**我们自己的 LVGL 入口传 `/dev/fb0`** |
| 优点 | `luncher_mini` 与所有 demo 立刻可用，改动最小 | 不破坏官方 AI Agent 的显示栈 |
| 风险 | 可能影响 AI Agent 显示栈（不确定） | 要自己写 LVGL 初始化（display + indev），多几十行 |
| 依据 | — | 日志 `lv_nuttx_lcd_create: lcd /dev/lcd0 opening` 说明**路径是参数传入**，不是写死 |

> **为什么本轮先不决定**：其他三项修复（NTP / 百度 / 表情）与屏幕**完全独立**，
> 而编译要几十分钟 —— 不该让机器空转等一个设计决策。
> 等这版出来后，可用 A 方案再编一次验证（改一行配置，重编很快）。
