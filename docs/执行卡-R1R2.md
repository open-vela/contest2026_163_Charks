## 卡片 A —— R3 识别率评估（半天，Windows，**不用板子**）

**为什么先做这个**：它用半天时间告诉你整个项目该怎么设计。如果识别率不行，"孩子说话→机器人回答"这个范式本身就不成立，后面都白做。

- [ ] **A1. 录样本**（30 分钟 + 找孩子的时间）

  找 1-3 个 2-3 岁的孩子，**每个录 10-15 条**，覆盖：

  | 类型 | 例子 |
  |---|---|
  | 常见需求 | 「我要喝水」「我想听歌」「抱抱」 |
  | 提问 | 「这是什么」「小兔子在哪」 |
  | 回答问题 | 「叫什么名字」「几岁了」「是什么颜色」 |
  | 叠词/幼儿化 | 「狗狗」「车车」「奶奶」「不要不要」 |
  | 长一点的句子 | 3 岁孩子能说的 |

  **录音要点**：距离 30-50cm 对着设备说（别贴手机话筒）；**安静与有噪声场景都要录**（分别打 `quiet` / `noisy` 标签）。

- [ ] **A2. 人工写下"孩子实际说了什么"**

  这是算字准率的基准，**不能省**。填进 `prototype/samples/ground_truth.csv`：

  ```csv
  filename,text,tag
  demo01.wav,我要喝水,quiet
  demo02.wav,我想听歌,noisy
  ```

- [ ] **A3. 转码成标准格式**（**必须做，否则识别率会被严重高估**）

  ```powershell
  # 【Windows】
  ffmpeg -i 原始录音.m4a -ar 16000 -ac 1 -sample_fmt s16 prototype/samples/demo01.wav
  ```

- [ ] **A4. 配密钥后跑评估**

  ```powershell
  # 【Windows】
  cd prototype
  copy config.example.yaml config.yaml
  # 编辑 config.yaml 填入百度 API_KEY / SECRET_KEY 与 DeepSeek Key
  py -3.13 -m pip install -r requirements.txt
  py -3.13 asr_eval.py
  ```

  **预期输出**：逐条明细（含音频规格警告）+ 按 tag 汇总 + 落档判定。

- [ ] **A5. 按结论定交互路线**

  | 整体字准率 | 交互范式 |
  |---|---|
  | **≥ 70%** | 自由对话：整句交给 LLM |
  | **50-70%** | 关键词 + 模板：只抽意图，其余预设回应 |
  | **< 50%** | 陪伴型：不追求听懂，机器人主动输出内容 |

- [ ] **A6. 回填**：《探板记录表.md》5.2 / 5.6 节填结论；若安静与有噪声差距 ≥15 个百分点，**记下要开 `AI_AGENT_AUDIO_PREPROCESS`**

**卡住了怎么办**

| 现象 | 处理 |
|---|---|
| 找不到 2-3 岁孩子录音 | 先用成人模仿幼儿语调录一批（**必须在结论里标注是模拟样本**，只能当上限估计） |
| 百度账号审核慢 | 先用 `pipeline.py --text "..."` 跑纯文本链路，把 prompt 与内容库先迭代起来 |
| 识别率低得离谱 | 先确认转成了 16kHz 单声道（脚本会警告）—— 这一步做错会导致误判 |

## 卡片 B —— R4 音频验证（1-2 天，板子）

**好消息**：R1 已确认 `/dev/audio/pcm0c`（采集）与 `pcm0p`（播放）都存在，且 `/data` 里有 7 个现成测试音频，**不用自己准备素材**。

### B1. 连接板子（30 秒）

```powershell
# 【Windows】
adb devices -l
# 预期：1234   device  product:adb dev  model:adb_board  device:NuttX
```

> 若看不到设备：换一根**数据线**（很多线只有供电）；看设备管理器有没有 `Debug Bridge`。

### B2. 先验证播放

- [ ] **B2.1 确认节点与素材**

  ```bash
  # 【板子】用 adb shell 或串口
  ls /dev/audio      # 预期：pcm0c  pcm0p
  ls /data           # 预期：on.wav startup.wav 1kHz.wav clocktick.wav spk1.wav sweep-x4b.wav test.pcm
  ```

- [ ] **B2.2 播放**

  ```bash
  # 【板子】
  aplay   /data/on.wav
  # 若上面不行，换另一个播放器：
  nxplayer /data/on.wav
  ```

  **预期**：扬声器/耳机出声。接扬声器用丝印 `SPK_L` / `SPK_R`；没有扬声器就用耳机口 `HPOUT`。

- [ ] **B2.3 顺带试音量与声卡信息**

  ```bash
  # 【板子】
  soundcard
  amixer
  ```

### B3. 再验证采集（数字 MIC，**本卡的主要风险点**）

- [ ] **B3.1 录音**

  ```bash
  # 【板子】
  arecord    /data/rec.wav
  # 或
  nxrecorder /data/rec.wav
  ```

- [ ] **B3.2 把录音弄回 Windows 用耳机听**（**不能只看文件大小**）

  ```powershell
  # 【Windows】
  adb pull /data/rec.wav ./rec.wav
  ```

- [ ] **B3.3 记录内存占用**

  ```bash
  # 【板子】播放/采集前后各跑一次
  free
  ```

### B4. 通过标准

- [ ] 能播放 wav 并**听到声音**
- [ ] 能录到 wav，**回放到 PC 上能听清人声**
- [ ] 录音格式确认为 16kHz / 16bit / 单声道（或记录了实际格式）
- [ ] 播放/采集前后的 `free` 输出已记录
- [ ] 音频测试工具的**实际可用命令**已确认（`aplay` vs `nxplayer`、`arecord` vs `nxrecorder`）

### B5. 卡住了怎么办

| 现象 | 处理 |
|---|---|
| 播放没声音 | ① 确认接的是 `SPK_L`/`SPK_R` 而不是 `LINEIN`；② 换耳机口验证是扬声器还是驱动问题；③ `amixer` 调音量；④ 换一个 wav 试 |
| 播放有杂音/断续 | 采样率不匹配或缓冲太小。先用 16kHz 单声道 wav 排除文件问题 |
| **数字 MIC 录不到声音** | ① 确认打开的是采集节点不是播放节点；② 检查 menuconfig 里 MIC/DMIC 相关项；③ 以 `EQ_AD51652.conf` / `EQ_AD52058.conf` 为线索去问客服这两颗器件对应哪路输入；④ **临时退路：先用 `LINEIN` 外接模拟麦克风把整条链路走通**，再回头啃数字 MIC |
| 命令找不到 | `help` 看全量列表（⚠️ nsh **没有** `grep`，过滤要在 PC 侧做） |

## 卡片 C —— R2 环境搭建 + 编译 + 烧录（2-3 天，虚拟机为主）

### C1. 装 VMware + Ubuntu 22.04【Windows + 虚拟机】

- [ ] 虚拟机内存 **8-12GB**、磁盘 **100-150GB**、核数为物理机一半、**路径不含中文**
- [ ] 装好 `open-vm-tools`，配好共享文件夹（`ls /mnt/hgfs/` 有内容）
- [ ] swap：内存 ≥16GB 可先不配（报了 OOM 再配）

> 详细参数见《环境搭建手册.md》第 2、4 节。

### C2. 装依赖【虚拟机】

- [ ] **按官方完整清单一次性装完**（见《环境搭建手册.md》5.1 节）

  **三个不能省的包**（漏了会失败，且报错不指向原因）：

  | 包 | 漏了会怎样 |
  |---|---|
  | **`libc6-i386`** | **`dragon` 打包工具无法执行** |
  | `gcc-multilib` / `g++-multilib` | 同上 |
  | `genromfs` | `pack` 阶段失败 |

- [ ] `git lfs install`（**必做**，报错隐蔽）
- [ ] `python3 -m pip install --user kconfiglib pyelftools cxxfilt`
- [ ] `repo` 可用（**用清华镜像装，Google 源国内不通**）

### C3. 拉源码【虚拟机】

```bash
# 【虚拟机】
mkdir -p ~/openvela && cd ~/openvela
curl -s https://mirrors.tuna.tsinghua.edu.cn/git/git-repo -o repo
chmod +x repo && sudo mv repo /usr/local/bin/

repo init -u https://gitee.com/open-vela/manifests.git -b dev-ai-contest-2026 -m openvela.xml
repo sync -c -j8
```

- [ ] 首次同步几个 GB，20-60 分钟，耐心等
- [ ] **同步后验证 4 件事**：

  ```bash
  ls vendor/allwinnertech/boards/r528/r528s3-gemini-s1/       # ① 板级目录
  ls packages/ai_agent/                                        # ② AI Agent 源码
  git -C vendor/allwinnertech branch --show-current            # ③ 应为 dev-ai-contest-2026
  ls vendor/allwinnertech/lichee/board/r528s3/gemini-s1_nand/  # ④ 打包目标（含 configs/ bin/ sign_config/）
  ```

### C4. 编译【虚拟机】

```bash
# 【虚拟机】
cd ~/openvela
./build.sh vendor/allwinnertech/boards/r528/r528s3-gemini-s1/configs/nsh -j2
```

- [ ] 编译零错误
- [ ] **链接阶段长时间无输出是正常的（LTO），不要中断**
- [ ] 校验四个产物：

  ```bash
  test -s nuttx/nuttx
  test -s nuttx/nuttx.elf
  test -s nuttx/nuttx.map
  test -s vendor/allwinnertech/lichee/board/r528s3/gemini-s1_nand/configs/nsh.fex
  ```

> ⚠️ **不要手工把 `nuttx.bin` 复制成 `nsh.fex`** —— POSTBUILD 会自动生成它。

### C5. 打包【虚拟机】

```bash
# 【虚拟机】新开一个终端
cd ~/openvela/vendor/allwinnertech/lichee/
source envsetup.sh
lunch_nuttx r528s3-gemini-s1     # ← 非交互带参数，不是"选 2"
pack
```

- [ ] 看到 `Dragon execute image.cfg SUCCESS !` 与 `pack finish`
- [ ] 固件名 **必须含 `gemini-s1`**：
      `rtos_nuttx_r528s3-gemini-s1_uart0_128Mnand.img`
- [ ] 记录固件大小与 SHA-256

> **三条致命细节**：
> 1. 只编译不 `pack` 得不到可烧录镜像（素材在 pack 阶段写入）
> 2. `pack` 前确认 `nsh.fex` 时间戳**已更新**，否则"烧录完还是旧代码"
> 3. `dragon` 缺 32 位库会直接跑不起来

### C6. 烧录【Windows】

- [ ] **C6.1 先备份 `/data`**（⚠️ 官方镜像的分区布局与出厂不同，多一个 `UDISK` 分区）

  ```powershell
  # 【Windows】
  adb pull /data ./data-backup
  adb pull /data/etc/wifi/wapi.conf ./data-backup/wapi.conf
  ```

- [ ] **C6.2 把固件从共享文件夹拷到 Windows**
- [ ] **C6.3 装全志 USB 线刷驱动 + PhoenixSuit**
- [ ] **C6.4 PhoenixSuit 操作五步**：

  1. 打开 `PhoenixSuit.exe`，选择"**一键刷机**"
  2. 选择 C5 产出的 Gemini 镜像（**文件名含 `gemini-s1`**）
  3. 选择"**全盘擦除升级**"
  4. **按住 `FEL`/下载键，同时短按 `RST`，再松开 `FEL`**
  5. 等待烧写完成并自动重启

  > ⚠️ 本板丝印是 `AP_RESET` / `BOOT_SEL0` / `BOOT_SEL1`，与资料里的 `FEL`/`RST` 需要对上。
  > 先试"`AP_RESET` = RST，`BOOT_SEL0` = FEL"，不行再换。**把有效组合记下来。**
  >
  > ⚠️ 烧录中**不要断电、不要拔线**。

- [ ] **C6.5 不要烧错**：文件名含 `256Mnand` 的是 DshanPi 产物，烧了会白屏/触摸错位

### C7. 首次启动检查【板子】

```bash
# 【板子】adb shell 或串口
uname -a             # 对比编译时间戳，确认是自己烧的固件
ps                   # 应看到 nsh_main
ls /dev              # 节点清单
ls /dev/audio        # pcm0c / pcm0p
free                 # 内存
ifconfig             # 网络接口
df                   # 文件系统容量（顺便确认 NAND 容量）
dmesg                # 启动日志 + 分区表（顺便确认 UDISK 是否消失）
```

- [ ] 能进 `nsh>`，`uname -a` 显示的是**你自己编的固件**
- [ ] 屏幕显示正常、触摸不错位
- [ ] 分区表已变成官方布局（`UDISK` 消失）
- [ ] 结果填进《探板记录表.md》4.4 / 4.5 节

## 卡住时的排查顺序

```
硬件接线 → 驱动/menuconfig 配置 → 自己写的代码 → 云端 API → 网络
```

99% 的 bug 在前三层。

**一类隐蔽问题的通用思路**：如果报错看起来跟你的操作没关系
（例如工具"找不到"却明明存在、pack 报怪异错误），
**优先怀疑缺系统库或 32 位兼容层**，而不是配置写错。
