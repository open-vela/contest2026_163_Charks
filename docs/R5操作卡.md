实测三种非交互方式**全部失败**：

| 方式 | 结果 |
|---|---|
| `ai_agent --help` | ❌ 挂住（把 `--help` 当普通输入） |

| `"help" \| adb shell ai_agent` | ❌ 超时，不响应 stdin |
| `"help" \| adb shell -t ai_agent` | ❌ 同样超时 |

**必须人工在终端里敲**。两种终端：

```powershell

# 进去后直接敲 ai_agent
```

```bash
# 方式 B：USB-TTL 串口，1500000 波特率，Flow Control = none
```

## 三、⚠️ 最高风险：**1970 年的系统时钟会让 HTTPS 证书校验失败**

### 3.1 问题

```
板子时间: Thu, Jan 01 08:50:09 1970        ← 无 RTC，上电从 0 开始
真实时间: 2026-09-19                         ← 差 56 年
```

**而百度和火山的 ASR/TTS 接口全走 HTTPS。** TLS 证书校验必须判断"证书是否在有效期内"，
**1970 年时所有证书都判为「尚未生效」**，校验必然失败。

**这是 `curl` 上的实测结论**：

```
$ curl https://www.baidu.com
curl: (60) Cert verify failed: BADCERT_NOT_TRUSTED      ← 默认校验：失败

$ curl -k https://www.baidu.com                          ← 跳过校验：成功（2443 字节）
$ curl -k https://aip.baidubce.com/oauth/2.0/token       ← 成功，返回业务 JSON
```

### 3.2 但 `curl` 不等于框架

`board/baidu_voice/` 调的是框架的 **`vela_https_request()`**（`src/infra/vela_tls.c`），
**证书策略完全在框架内部**，我们的代码管不着。

**所以：框架到底校不校验证书，目前未知。** 两种可能：

| 可能 | 后果 |
|---|---|
| 框架做校验 | ❌ **`net_test` / `voice_*` 会因 TLS 失败** —— 这是最可能的 |
| 框架不校验（或内置 cert 且不查时间） | ✅ 可以直接往下走 |

**`net_test` 就是第一次判定**。如果它报 TLS/证书相关错误，基本可以确认是这个原因。

### 3.3 如果确认是时钟问题——修时间的三条路**都被实测堵死了**

| 尝试 | 结果 |
|---|---|
| `date -s "2026-09-19 12:32:00"` | ❌ `nsh: date: argument invalid`（不支持设置） |
| `ntpcstart` | ❌ 服务器写死为 `0.pool.ntp.org`（国外，**校园网封 UDP 123**），`samples: 0` |
| `ntpcstart ntp.aliyun.com` | ❌ 该参数被忽略，仍 `samples: 0` |
| 找 `/etc/ntp.conf` 等配置文件 | ❌ **全部不存在**（服务器地址编译在固件里） |

> `ntp.aliyun.com`（`203.107.6.88`）**ping 通，75ms** —— 网络没问题，
> 是**服务器地址写死在编译期**。

**唯一解法：重新编译固件，把 NTP 服务器换成国内地址**（`CONFIG_SYSTEM_NTPC_SERVER`）。
这正好和"集成百度后端"是同一次编译，**可以合并做掉**。

## 三·五、成本与免费方案（2026-09-19 调研）

### 3.5.1 一个容易被忽略的事实：**"跑通"这件事几乎不花钱**

不管用哪家，**跑通一次闭环的成本 = 1 次 ASR + 1 次 TTS**。哪怕完全没有免费额度，
按量计费也就是**几分钱**；调到跑通大概几十到几百次调用，**总共几毛钱**。

**而"换一家免费服务"的成本反而更高**：

| 项 | 成本 |
|---|---|
| 重开云编译服务器 | **十几元**（按小时计费 × 2-4 小时） |
| 集成 + 调试另一个后端 | **1-2 天** |
| 合计 | **远高于那几毛钱** |

> ⚠️ **可能的误解来源**：火山**方舟大模型**（豆包）确实不便宜，
> 但**语音**（TTS/ASR）是完全不同的计费体系，单价低得多。两者别混在一起看。

### 3.5.2 各家的免费额度（2026-09-19 核实）

**百度智能云语音**（官方文档 `ai.baidu.com/ai-doc/SPEECH/Wl9mh4doe`，更新于 2026-07-14）：

| 服务 | 个人认证 | 企业认证 |
|---|---|---|
| **短语音识别（普通话）** | **5 万次** | 10 万次 |
| **短文本在线合成（基础/精品音库）** | **5 万次** | 10 万次 |
| 实时语音识别 / 音频文件转写 | 10 小时 | 10 小时 |
| 臻品音库合成 | 1 万次 | 2 万次 |
| 离线合成授权（试用） | 2 台设备 | 5 台设备 |

> ✅ **官方原话**：「免费额度自用户在语音技术控制台**首次登录发放后生效，并永久有效**」
> 「每个账号根据认证信息**仅发放一次**」

**5 万次够用多久**：一次闭环消耗 2 次（ASR + TTS）→ **约 2.5 万轮对话** ✓ 足够开发全程。

正文却无任何价格 ✗）。**请到你自己的火山控制台查看实际额度和账单** —— 那里是唯一准确的。

**其他备选**：讯飞 500 次/天；阿里云 15 小时/月。（都要自己写后端，见下）

## 四、下一步的两条路

### 路 A：先跑火山基线（不需要重编译）

固件已内置火山后端。**这是最快能看到"说话→识别→回答→播放"闭环的路径。**

#### A.1 已有的凭据

API Key 已存到 **`prototype/.secrets/volc_api_key.txt`**（已 gitignore，不会提交）。

> ⚠️ **安全提醒**：这把 key 出现在聊天记录里了，**建议用完后到火山控制台作废重发**一把。

#### A.2 ⚠️ PC 端验证的结果（诚实说明）

我在 PC 上试了两种鉴权方式，**都被 401 拒绝**：

| 尝试 | 结果 |
|---|---|
| `POST ark.cn-beijing.volces.com/api/v3/chat/completions` + `Bearer <key>` | ❌ 401 |
| `GET  ark.cn-beijing.volces.com/api/v3/models` + `Bearer <key>` | ❌ 401（空 body） |
| 同上 + `X-Api-Key: <key>` | ❌ 401 |

**但这不代表 key 无效**，理由有三：

1. 火山**语音**（openspeech）的鉴权**不是 `Bearer <apikey>`** 那套方案（它是 `Bearer;<token>` + `app_id`）
2. 我试的"列模型"接口**可能根本不存在**，对未知路径返回 401 也常见
3. key 的 protobuf 载荷里字段 2 是 varint `2125869611`（若按 Unix 秒解释 ≈ **2037 年**），**不像已过期**

**结论：这把 key 该由板端来验，不该由 PC 来验。** 板端正好有专门的命令。

#### A.3 ★ 板端验证（**这是下一步要做的**）

```bash
# 【终端】进板子
adb shell

# 【板子 nsh】进 agent
ai_agent
#   → 提示符变为 vela>

# 第 1 步（不需要密钥，先做）：确认网络与 TLS 是否被 1970 时钟卡住
net_test

# 第 2 步：配火山 key
set_volc_key <prototype/.secrets/volc_api_key.txt 里的那一行>

# 第 3 步：切到火山 TTS 并测试
set_voice_tts volcengine
voice_test_tts 你好世界
#   预期：回显生成的 PCM 字节数，产出文件
#   若报 TLS / 证书错误 → 就是 1970 时钟那个问题（见第三节）
```

> **好消息**：**TTS 只需要这一把 key，不需要 `app_id`** —— 所以上面三步就能验证 key 到底能不能用，
> 不用先去凑齐 `set_volc_asr` 要的 `app_id` + `token`。

#### A.4 ASR 还需要额外的凭据（暂缺）

如果要验证**语音识别**，还需要火山语音的 **App ID + Access Token**：

```bash
set_volc_asr <app_id> <token> <resource_id_or_cluster>
set_voice_asr volcengine
voice_test_asr /data/agent/tts_out.pcm
```

**这两样目前没有** —— 需要到**火山引擎控制台 → 语音技术 → 应用管理**里拿
（不是"访问控制 → API Key"那个页面，是两个不同的地方）。

#### A.5 三条可能的走向

| `voice_test_tts` 的结果 | 含义 | 下一步 |
|---|---|---|
| ✅ 产出 PCM 文件 | key 有效 **且** TLS 没问题 | 直接试 `voice_start` 跑闭环 |
| ❌ 报 TLS / 证书错误 | key 可能有效，但**卡在 1970 时钟** | 走路 B（重编译修 NTP） |
| ❌ 报鉴权 / key 相关错误 | 这把 key 不是语音服务用的 | 去火山**语音技术**控制台重新拿凭据 |

### 路 B：集成百度后端（需要重新编译）

要把 `board/baidu_voice/` 集成进源码树，**顺带把 NTP 服务器也改掉**。

集成步骤见 `board/baidu_voice/README.md` 第三节，核心是：

```bash
# 在源码树里
cp board/baidu_voice/baidu_*.h   packages/ai_agent/include/voice/
cp board/baidu_voice/mic_route.h packages/ai_agent/include/voice/
cp board/baidu_voice/baidu_*.c   packages/ai_agent/src/voice/
cp board/baidu_voice/mic_route.c packages/ai_agent/src/voice/
# 再把 Kconfig.fragment 追加进 packages/ai_agent/Kconfig
# 并在注册处调用 baidu_asr_register() / baidu_tts_register()
```

> ⚠️ **编译环境目前不可用**：云编译服务器（`139.224.52.7`）**SSH 超时，已释放**。
> 需要重新开一台（见 `scripts/云主机构建指南.md`），或改用本地 Ubuntu 虚拟机。

### 推荐顺序

1. **先进 `ai_agent` 敲 `net_test`** ← 现在就能做，不需要密钥、不需要重编译
2. 拿 `net_test` 的结果来决定：
   - 通过 → 走**路 A**（找火山密钥，快速看闭环）
   - TLS 失败 → 直接走**路 B**（重编译，顺便修 NTP）
3. 无论走哪条，**最终都要做路 B**（百度后端是项目的既定目标）
