### 0.1 下发 API Key（烧录后必做）

```sh
mkdir -p /data/etc/superchild
echo <你的key> > /data/etc/superchild/stepfun.key
```

adb 或串口 nsh 都行。

**为什么 Key 不在固件里**：写进固件等于公开（实测：编好的镜像
`strings` 一下就能抓到 WiFi 明文密码）。放 `/data`（YAFFS 可写分区，
重启保留）之后，固件可以随便传、重刷、送人都不泄露密钥。

**为什么必须去掉换行**：`echo` 会带一个 `\n`，而带换行的 key 发出去是
鉴权失败 —— 报错完全看不出是换行导致的。`sc_key.c` 已经会去掉首尾空白，
但如果你用别的方式写入，记得别把换行留在里面。

可选：`/data/etc/superchild/persona.txt` 可以覆盖内置的角色提示词。

其余步骤都在下面的脚本里。

## 3. 没有板子时的端到端验证（在 ECS 上，1 分钟）

**这一步强烈建议先做。** 它把"网关 + StepFun"整条链验证干净，
之后上板出了问题就只可能是板子侧的事。

```bash
cd /opt/superchild

# 3.1 生成一段测试语音（用 StepFun 自己的 TTS，最省事）
export STEPFUN_API_KEY=你的KEY
/opt/superchild-venv/bin/python tools/make_test_audio.py \
    --tts "小星星，一闪一闪亮晶晶" --out /tmp/test16k.pcm

# 3.2 假板子：上行这段语音，把回话录下来
/opt/superchild-venv/bin/python tools/fake_board.py \
    --host 127.0.0.1 --pcm /tmp/test16k.pcm --out /tmp/reply.wav \
    --hold 14 --delay 8
```

**看什么**：

```
[17:19:22]    ↓ 状态 → LISTENING          ← VAD 听到孩子说话了
[17:19:27]    ↓ 状态 → THINKING           ← 说完了，在思考
[17:19:27]    ↓ 字幕 → 你说：小星星，一闪一闪亮晶晶
[17:19:28]    ↓ 字幕 → 小满：小星星，一闪一闪亮晶晶，真好看呀
[17:19:28]    ↓ 表情 → SINGING            ← 情绪引擎把"小星星"判成了唱歌
收到下行音频 : 299448 字节 = 9.36 秒
```

| 现象 | 含义 |
|---|---|
| 转写正确 | **16k→24k 上行重采样是对的**（错了会转成乱码） |
| `收到下行音频` 有几秒 | 下行通了 |
| `--out /tmp/reply.wav` 用播放器听**语速音调正常** | **24k→16k 下行重采样是对的**（错了会变调） |
| 表情帧有变化 | 情绪引擎在工作 |

⚠️ `--delay 8` 不是随便给的：网关会先播一遍开机问候，而**半双工闸门
在问候期间不收上行**。立刻发语音的话前半段会被整车丢掉，
看起来像"孩子说了但机器人没反应"—— 是测试姿势问题，不是链路问题。

## 4. 编译固件（在 ECS 上，40 分钟起）

> ### ⚠️ 编译前必须先看第 4.0 节：WiFi 凭据
>
> **不填 WiFi，烧进去之后开机什么都不会发生** —— 板子连不上网关，
> 界面上只有一张脸和"WiFi 未连"角标。这是"开机即对话"里最容易漏的一环。

### 4.0 WiFi：开机自动联网（必做）

板子的开机联网脚本（`rcS.nsh` → `start_wifi.sh`）**是坏的**，
两处都断（逐文件核对源码树得出，2026-09-20）：

| 断点 | 现象 |
|---|---|
| `/data/etc/wifi/wapi.conf` **不在打包素材里** | `rcS.nsh` 里的 `if [ -f ... ]` 为假 → 脚本一次都不会执行 |
| `start_wifi.sh` 用 `grep -oP` + `$(...)` 取值 | **板上没有 grep**，nsh 也不支持 `$(...)` → SSID/PSK 全是空 |

真正能用的机制是**官方 netinit 的编译期配置**（`netinit_associate.c`）：

```c
load = wapi_load_config(ifname, NULL, &conf);
if (!load) {                       // 读不到 wapi.conf 才用这里
    conf.ssid       = CONFIG_NETINIT_WAPI_SSID;
    conf.passphrase = CONFIG_NETINIT_WAPI_PASSPHRASE;
    conf.bssid      = NULL;        // ← 不带 BSSID，这点很关键
}
if (conf.ssidlen > 0) wpa_driver_wext_associate(&conf);
```

**怎么用**：编译时把 SSID/密码作为环境变量传进去，集成脚本会自动同步到
`CONFIG_NETINIT_WAPI_SSID` / `CONFIG_NETINIT_WAPI_PASSPHRASE`：

```bash
cd /root/build
WIFI_SSID="你家的WiFi名" WIFI_PASS="密码" \
    nohup bash scripts/ecs_build.sh > /root/fw_build.log 2>&1 &
```

> 也可以单独跑集成：`WIFI_SSID=... WIFI_PASS=... bash scripts/integrate_superchild.sh`

**当前固件已内置凭据**（SSID=`wifi`），由编译时环境变量注入，仓库里不含密码：

```bash
WIFI_SSID='wifi' WIFI_PASS='<路由器密码>' nohup bash scripts/ecs_build.sh > /root/fw_build.log 2>&1 &
```

**三个必须知道的坑**：

1. **不要用 `wapi.conf`**。那份配置里 `bssid` 是**必填**字段，而填了就
   把网卡钉死在某个 AP 上，**换个网络必然连不上**（项目里踩过：
   `lichee` 里的样例写死了 `be:c1:a6:ff:d6:5e`）。编译期配置不带 BSSID，
   换网络也能连。
2. **密码不要写进 defconfig 提交**。用环境变量传。集成脚本只在
   显式给了 `WIFI_SSID` 时才写。
3. **⚠️ 板级 defconfig 原本把加密方式写成了 TKIP**（`CIPHERMODE_TKIP` +
   `ALG_TKIP`），而现代路由器基本都是 **WPA2-AES（CCMP）专用** ——
   配 TKIP 会关联失败，且失败现象很模糊（`No Assoc Network After Scan Done`），
   看起来像信号问题，非常容易往错的方向排查。

   集成脚本现在已经把这几行**删掉**，让 Kconfig 用它自己的默认值
   （`AUTHWPA_WPA2` + `CIPHERMODE_CCMP` + `ALG_CCMP`），这与厂商自己那份
   能用的 `wapi.conf` 样例（`"auth":4,"cmode":8,"alg":3`）一致。

   编译后可以这样核对：
   ```bash
   grep -E '^CONFIG_NETINIT_WAPI_(AUTHWPA|CIPHERMODE|ALG)' /root/openvela/nuttx/.config
   # 期望：AUTHWPA=0x00000004  CIPHERMODE=0x00000008  ALG=3
   ```

**兜底**：即使上面都对了，如果板子和路由器**同时上电**，netinit 那一次
关联可能赶在路由器就绪之前，而它**不会再重试**。所以应用里有一个 WiFi
守卫任务：开机后检查 `wlan0` 有没有 IP，没有就按 3/5/7…秒递增重试
最多 12 次（约 1 分钟），并把状态显示在屏幕角标上。

**屏幕角标的含义**（角标是排查的第一手信息）：

| 角标 | 含义 | 先查什么 |
|---|---|---|
| （无） | 已连网关 | 正常 |
| `o 连接中` | WiFi 通了，正在连网关 | 安全组有没有放行 8900 |
| `! WiFi 未连` | 网卡在但没拿到 IP | 密码对不对、路由器在不在、信号强度 |
| `! 没有 wlan0` | 网卡都没起来 | WiFi 驱动 / 固件（RTL8733BS） |
| `x 掉线` | 连过又断了 | 网关服务是否在跑、网络是否掉了 |

> **为什么要专门摆出 WiFi 状态**：「没联网」和「它不理我」在孩子眼里
> 表象完全一样（都是说了没反应），但排查方向差得很远。
> 不摆出来就只能靠猜。

## 5. 烧录与上板验证

烧录见 `烧录操作卡.md`。⚠️ 前置：关闭 Windows「内存完整性」(HVCI)，
否则全志 FEL 驱动被拦，PhoenixSuit 永远看不到设备。

烧完之后：

```bash
adb shell "uname -a"                  # 确认编译时间戳是刚才那次
adb shell "ps"                        # 应该看到 superchild 在跑
adb shell "free"                      # 看内存余量
```

**开机后应该直接看到一张笑脸**，右下角没有角标 = 已连上网关。

### 逐个验证（从易到难）

| 顺序 | 看什么 | 不对时先查 |
|---|---|---|
| 1 | **屏幕**上有脸 | 白屏 → fb_path 该用 `/dev/fb0`；花屏 → 屏参不对 |
| 2 | 表情每几秒眨一次眼 | 不眨 → UI 循环没跑起来（看 `ps`、看串口日志） |
| 3 | 左上角角标消失 | 一直在"连接中" → 安全组没放行 8900 |
| 4 | 对着它说话，**眼睛会变** | 不变 → 麦克风没通（看串口有没有 `microute` 的告警） |
| 5 | 它开口回答 | 不答 → 看网关日志的 `孩子说：` 有没有内容 |
| 6 | 说话时**嘴跟着动** | 嘴不动 → 播放任务没跑（看有没有 `播放失败`） |
| 7 | 夸它一句，表情变"得意/开心" | 不变 → 看网关日志里情绪引擎有没有命中 |

### 串口日志里的关键行

```
[sc_audio] capture opened: 16000Hz 1ch (hw) 16bit      ← 采集通了
[sc_audio] playback opened: 16000Hz 1ch 16bit          ← 播放通了
[microute] capture route ready                          ← 麦克风通路 OK
[sc_net] 已连上网关                                     ← 网络 OK
```

如果看到 `[microute] ... routes failed` → 麦克风通路没使能好，
录到的会是全零；这时查 `sc_microute.c` 里的控制项名称是否与固件版本一致
（日志会打印具体是哪个名字找不到）。

## 6. 常见问题速查

| 现象 | 最可能的原因 | 怎么确认 / 怎么解 |
|---|---|---|
| 屏幕白屏 | fb_path 不对 | 试 `/dev/fb0`（改 `sc_main.c` 或关 `CONFIG_LV_USE_NUTTX_LCD`） |
| 有脸但表情不动 | LVGL 被别人初始化了 | `ps` 看有没有 mini_memo；集成脚本已默认关掉它 |
| 一直"连接中" | 安全组没放行 8900 | 网关侧 `ss -tlnp` 有监听但外网连不上 = 安全组 |
| 说话没反应 | 麦克风通路 / 增益 | 串口找 `microute`；网关日志找 `孩子说：` |
| 它答了一半就停 | 半双工闸门把它自己的声音当成孩子在说 | **正常**（闸门开着就不该发生）；若仍出现，调大 `playback tail` |
| 越聊延迟越大 | 下行泵积压 | 网关日志找 `下行积压`；确认 pump 在跑 |
| 声音变调/语速不对 | 采样率配错 | 网关 `audio.api_sample_rate` 必须是 **24000** |
| 它自问自答 | 回声泄漏太强 | 确认 `half_duplex = true`；或调小音量 |
| 情绪表情不出现 | 情绪引擎没命中 | 控制台能看到命中的 label；不命中就补 `emotion.py` 的词表 |

## 8. 改板端的流程

```powershell
# 1. 改本地 board/superchild/*.c
# 2. 传上去
scp -i $k -r board "${h}:/root/build/"
# 3. 重新构建（集成脚本会覆盖 packages/demos/superchild/）
ssh -i $k $h "sed -i 's/\r$//' /root/build/board/superchild/*; cd /root/build && nohup bash scripts/ecs_build.sh > /root/fw_build.log 2>&1 &"
# 4. 盯日志
ssh -i $k $h "grep -n 'error:' /root/fw_build.log | head"
```

> ⚠️ `sed -i 's/\r$//'` 不能省：Windows 上编辑过的 `.c` 带 CRLF，
> 传到 Linux 后编译能过，但**行尾会进到字符串字面量里**，
> 导致日志/字幕里多出莫名其妙的东西。所有上传的脚本和源码都该过一遍。

## 9. 调表情视觉（上板之后必做的一件事）

`board/superchild/sc_face.c` 里的 `g_looks[]` 表是**唯一需要改的地方**，
24 行、每行 17 个数。**这些数字全部是按屏幕短边比例推定的，没有上板验证过。**

调法：

1. 打开控制台 `http://47.111.175.10:8800/`
2. 下拉框切到要调的表情（24 个都在里面）
3. 对着屏幕看哪里不对 → 改表里对应的列 → 重新编译
4. 表头的列名对照：

```
eye_h eye_w eye_dy shape shape_l shape_r brow_l brow_r brow_dy
mouth_w mouth_h mouth_dy corner cheek deco anim amp
```

先确保这 6 组**彼此能一眼分清**（这是"表情看不出在变"的解药）：

```
HAPPY vs LAUGHING    眯眼笑 vs 大笑
CURIOUS vs SURPRISED 瞪大眼小嘴 vs 更大眼圆嘴
SAD vs CONFUSED      垂眼扁嘴 vs 眯眼小圆嘴
PROUD vs SHY         眯眼抿嘴 vs 垂眼最浓腮红
EXCITED vs CELEBRATE 星星眼大张嘴 vs 眯眼撒花
SLEEPING vs BORED    闭眼飘 Z vs 半眼飘忽
```
