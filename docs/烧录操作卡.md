# 烧录操作卡 — r528s3-gemini-s1（Gemini-S1）

> 2026-09-18 实录。这张卡把"按键身份"和"烧录步骤"一次定死，
> 以后不用再摸索。所有结论都有实测证据，不是推测。

---

## 一、按键身份（本次实测确认 ✅）

板上丝印只有 `AP_RESET` / `BOOT_SEL0` / `BOOT_SEL1` 三个名字，
**没有"FEL"字样**——这是之前一直卡住的真正原因。

实测证据（USB 监视日志）：

| 时间 | 操作 | 结果 |
|---|---|---|
| 22:48:22 | 单按 `AP_RESET` | `uptime` 归零 → **复位成功** |
| 22:48:49 | 按住 `BOOT_SEL0` + 点按 `AP_RESET` | ADB 断开、出现 `VID_1F3A&PID_EFE8` → **进入 FEL** |

**结论：**

| 丝印 | 真实身份 | 用途 |
|---|---|---|
| **`AP_RESET`** | **RST（复位）** | 重启板子 |
| **`BOOT_SEL0`** | **FEL** | 进烧录模式 |
| `BOOT_SEL1` | 备用（推测为启动介质选择） | 本流程不需要 |

**位置**：板子**底部边缘**那一排小按键。丝印排布：

```
上排:   AP_RESET        BOOT_SEL1        BOOT_SEL0
下排:   HOME            ENTER            MENU
```

---

## 二、进入烧录模式（标准动作）

```
1) 按住 BOOT_SEL0 不松手
2) 另一只手点按一下 AP_RESET（短按，松开）
3) 再松开 BOOT_SEL0
```

**判断成功的标志**：

- 屏幕**保持不亮**（不进系统）
- `adb devices` 里**看不到**板子
- 设备管理器出现 `USB Device(VID_1f3a_PID_efe8)`

只要屏幕亮着进系统了，就是没进 FEL，重复上面三步即可。

---

## 三、前置条件：内存完整性必须关闭 ⚠️

**这是这次卡住的核心原因。**

全志的 FEL 驱动（`USBDrv_AMD64.sys`，2013 年）**无法在 Windows「内存完整性」开启时加载**：

```
Code Integrity: ...USBDrv_AMD64.sys that is not compatible with
hypervisor enforcement. Failure bitmap 0x2. Status 0xC0000220.
```

驱动装是装上了，但每次加载都被拦，事件日志里刷屏：

```
Kernel-PnP: The driver \Driver\usbUDisc failed to load.
```

**现象**：PhoenixSuit 里设备死活出不来（或显示驱动错误）。

**修法**：关闭「内存完整性」并重启。

- **图形界面**：Windows 安全中心 → 设备安全性 → 内核隔离 → 内存完整性 → **关**，重启
- **命令行**（管理员）：

```powershell
Set-ItemProperty `
  -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" `
  -Name Enabled -Value 0 -Type DWord
# 然后重启电脑
```

> 这个拦截**无法通过白名单豁免**（`bitmap 0x2` 表示驱动用了 HVCI 无法虚拟化的内存特性），
> 所以只能关掉 HVCI。**刷完机可以再打开**，不影响已烧录的固件。

## 四、烧录步骤

### 0. 前置

- [ ] 内存完整性已关闭 **且已重启**
- [ ] PhoenixSuit 已打开（`tools/PhoenixSuit/PhoenixSuit.exe`）
- [ ] 固件镜像在：`firmware/rtos_nuttx_r528s3-gemini-s1_uart0_128Mnand_minidisplay.img`（27.9 MB）

### 1. 让板子进 FEL

按【第二节】的三步动作。**保持板子在这个状态**（屏幕不亮）。

### 2. 确认电脑认到设备

设备管理器里应出现 `USB Device(VID_1f3a_PID_efe8)`，
**且没有黄色感叹号**。

有感叹号 = 驱动仍未加载，回【第三节】检查 HVCI。

### 3. PhoenixSuit 烧录

```
① 点「一键刷机」/「固件」标签
② 选择镜像文件：
     firmware/rtos_nuttx_r528s3-gemini-s1_uart0_128Mnand_minidisplay.img
③ 确认勾选「全盘擦除」（首次烧录必须先全盘擦除）
④ 点「升级」，等待进度条走完
⑤ 完成后断电重启板子
```

> ⚠️ **首次烧录一定要全盘擦除**。出厂固件的分区布局和我们构建的可能不同，
> 不擦除会残留旧分区表，导致启动异常。

### 4. 验证

重启后：

- 屏幕应点亮，显示 NuttX 的启动界面
- `adb devices` 能看到板子
- `adb shell uptime` 能返回运行时间

## 五、万一还是不行

| 现象 | 检查 |
|---|---|
| 电脑不认设备 | HVCI 是否真的关了？`Get-CimInstance Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard` 看 `SecurityServicesRunning` 不应包含 `2` |
| 设备有黄色感叹号 | 设备管理器里卸载设备 → 重新进入 FEL → 让它重新装驱动 |
| PhoenixSuit 报设备失败 | 换一个 USB 口（优先主板直出的 USB 2.0 口，不要用前面板/Hub） |
| 进不去 FEL | 三步的**顺序**是关键：先按住 `BOOT_SEL0`，再点 `AP_RESET`，**最后才松开 `BOOT_SEL0`** |
| 烧录中途失败 | 拔电重来。NAND 写入中断一般不会砖，BROM 的 FEL 始终可用 |

## 六、备用路径（万一驱动始终搞不定）

FEL 的通信协议走 **WinUSB** 是可行的替代方案：

1. 用 **Zadig** 把 `VID_1F3A&PID_EFE8` 的驱动替换成 **WinUSB**（微软签名，HVCI 不拦）
2. 用 **`xfel`**（支持 R528/D1，走 libusb）读写

**但要注意**：`xfel` **不支持 NAND 写入**（只支持 SPI NOR / DRAM / eFuse）。
所以这条路只能用于**临时把固件加载到 RAM 里跑**，不能替代正式烧录。

**结论**：正式烧录仍应以 PhoenixSuit 为准，HVCI 该关就关。
